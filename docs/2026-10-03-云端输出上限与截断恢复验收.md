# 云端输出上限与 length 截断恢复验收

日期：2026-10-03。起因：用户报告对话报「模型输出未完整结束：length」。查证后确认根因在
`api.limit_tokens` 关闭时云端限额被硬编码兜底顶掉、概念对话通道写死 2048、以及输出预留
没有把 reasoning token 算进去。本轮按用户要求实施三处修复（设置真正生效 / 推理预留 /
截断可恢复）。

本文件只记录本轮行为与验证；旧的「概念通道最多2048」说法见
`2026-10-02-普通对话响应优化验收.md`，**以本文件为准**。

## 使用与行为

界面：API 配置 → 高级设置 →「上下文、token 与思考策略」。

- 新增「云端对话最大回复 token」（`api.dialogue_max_tokens`，默认 2048，范围 128–32768）。
  对话类回复（概念解释、非快速档的寒暄）的**正文**上限 = `min(云端最大回复 token, 这一项)`；
  寒暄＋思考关闭仍走 512 的快速档。设置既能调小也能调大，不再被写死的 2048 压住。
- 新增「云端对话最大回复 token」（`api.dialogue_max_tokens`，默认 2048，范围 256–32768）。
  对话类回复（概念解释、非快速档的寒暄）的**正文**上限 = `min(云端最大回复 token, 这一项)`；
  寒暄＋思考关闭仍走 512 的快速档。设置既能调小也能调大，不再被写死的 2048 压住，但不会
  超过「云端最大回复 token」预算（或未勾选限制时的 8192 兜底）。
- 「对云端 API 启用限制」不勾选时的兜底语义写在界面说明里：云端上下文按 131072、分析类
  回复按 8192；「云端对话最大回复 token」始终生效但受回复预算压着。
- 思考档位（低/中/高/自动/关）会额外留出推理额度（1024/4096/8192/4096/0），
  `max_tokens = 正文 + 推理额度`；`Budget.reserve` 与 `cloud_agent` 的上下文校验同口径。
- 上下文装不下「正文 + 推理」时先缩推理额度（正文必须放得下），不会因此把整轮判成失败；
  正文都放不下时仍报原来的「最小报告上下文与输出预留无法容纳，请缩小范围或增加上下文设置」。
- 服务端拒绝这次请求的输出上限（4xx 提到 `max_tokens`/`max_completion_tokens`）时按
  「推理先让位」降额并**重新开一轮**重试一次：报错点名上限就按上限给正文优先、推理吃剩余；
  读不出数字就先让掉推理额度、正文维持原样；推理本来就是 0 才砍正文（地板 256）。
  工具阶段不做这个重启（重开会多算一次 `planning_rounds`，用户明确要求的对象操作会被
  「未授权追加对象操作」挡掉）；既有「思考档位被拒」的处理不变。
- 流式对话第一次以 `length` 结束时自动续写一次（带上已写内容的结尾部分；没被拒过上限时
  一个字都没流出来才沿用原来的失败路径。
- 分析路径（`execute`/`report` 不传 `on_text`）**本来就不进** `length` 判断，它的截断一直由
  SDK 的输出校验/上游报错体现；本次改动不动它（见下面「已知问题」）。

## 局限与未覆盖

- 未使用真实云端 API 与用户真实音频做真机验证（无凭据/材料）；所有端到端验证使用本地
  SSE 夹具与 FunctionModel。
- 既有的「临时失败（408/429/5xx/超时）有限重试」仍在 `for attempt` 里原地 `continue`：
  它只在非流式路径有效，流式路径会撞上面那条断言。本轮未改动它（不在本次范围内），
  已记录为已知问题。
- 输出上限降额只在**非工具阶段**生效：工具阶段收到「输出上限被拒」的 4xx 仍按失败收尾
  （改动前的行为），因为整轮重启会让 `planning_rounds` 多加一次、把用户明确要求的对象
  操作挡成「未授权追加对象操作」。
- `ai/ai_config.json`（用户配置）未改动；本轮只在代码默认值与界面里新增设置。
