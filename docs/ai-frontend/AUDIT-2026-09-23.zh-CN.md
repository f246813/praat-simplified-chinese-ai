## 优先修复的缺陷

1. **P0：纠音标注文件无法导回，JSON 报告会被清理。** `ai/praat_ai/report.py:69` 写 `class = "PointTier"`，Praat 的类名是 `TextTier`（`fon/praat_TextGrid_init.cpp:1944`）。用 `parselmouth.read()` 读当前输出得到 `Class "PointTier" not recognized.`；只把类名换成 `TextTier` 就能读入。`sys/praat_python.cpp:1045-1082` 对输出目录中所有文件执行 `Read from file:`，捕获并清除错误后删除整个目录。JSON 不是 Praat 对象，因而报告不会以对象形式导入，原路径也随目录删除而失效。设计文档的“TextGrid、PNG、JSON 均自动导回”至少对前两者中的 TextGrid 和 JSON 不成立。先修 TextGrid 格式并增加原生读取测试；报告应保存到持久位置并给出可打开路径，明确 JSON 的交付契约，再验证 PNG 的导入行为。现有 `test_report.py` 只检查文件包含 `AI_Errors`。
2. **P0：同一录音也可能被报成发音错误。** `ai/praat_ai/ui.py:25-36,153` 把标准音位按时长等分；`ai/praat_ai/pronunciation.py:185-226` 只对齐学习者，标准音特征仍按等分边界取。隔离复现：同一合成 WAV 同时作标准和学习者，真实段界为 0.2 秒；标准侧等分为 0.5 秒，学习者侧给正确 0.2 秒边界，结果报出一个 `spectral_centroid` 错误，分数 `1.2615` 超过默认阈值 `1.25`。应先建立两侧可核验的音位边界，允许使用已有 TextGrid 或同一对齐器，并以“相同音频、相同音位边界、零假阳性”回归。仅把阈值调高会掩盖根因。
3. **P0：陈旧 PID 文件可能杀错进程。** `ai/praat_ai/control.py:290-301` 读取 `runtime/qwen.pid` 后直接 `_kill_process(process_id)`；按端口停止的另一条路径检查进程名，但这里没有检查可执行文件、端口或启动时间。PID 被系统复用时，菜单停止服务或切换模型可能终止无关进程。应在 kill 前核实 PID 所属服务和端口，身份不符时清理陈旧 PID 并拒绝终止；用 mock 覆盖“陈旧 PID 指向无关程序”。
4. **P1：Praat 菜单里的独立 API 配置窗口只改配置，不执行服务切换。** `ai/praat_ai/api_settings.py:534-557` 保存后只在 `on_saved` 存在时通知；`run_standalone()` 创建窗口时没给回调。对话窗口入口在 `ai/praat_ai/chat.py:1946-1971` 才会发送 `stop-local-service` 或 `start-local-service`；另一个窗口检测配置改动时只调用 `reload_config()`（`chat.py:2331-2349`）。因此从菜单启用 API 后旧本地服务未按 `api.stop_local_service` 停止；从菜单关闭 API 后本地端口若为空，下一次请求可能仍报连接拒绝。两入口应使用同一配置切换事务和进程策略；用临时配置与假进程验证双方向，再做 GUI 回归。
5. **P1：多步对话沿用请求开始时的对象快照。** `ai/praat_ai/chat.py:2160-2205` 只在开头解析一次 `chat_context.tsv`；`_run_agent_turn()` 后续各步仍用同一个 `ToolContext`，而 Praat 在执行后会刷新上下文（`sys/PraatAiControl.cpp:510`）。批处理复现“截片段，然后把它改名”：第二步省略 object 时脚本写 `selectObject: 1`，结果原音频变 `renamed`、新片段仍叫 `clip`；即使模型正确写 `object=2`，旧快照也报“对象列表里没有 2”。每个会改变对象列表的动作后应刷新执行上下文，按新对象 ID 和用户指代重新解析；验收要覆盖新增、改名、删除、选中变化以及模型给出新 ID 的路径。
6. **P1：同一 GGUF 的预设切换没有应用运行参数。** `ai/praat_ai/control.py:376-404` 的服务一致性只比较模型名；不同预设若共用模型文件，但上下文窗口、GPU 层数或投影文件不同，`apply_preset()` 会更新配置却不重启已运行服务。`ai/praat_ai/config.py:198` 虽解析预设中的 `threads`，`ai/praat_ai/presets.py:147-163` 的 `apply_preset_to_profile()` 没应用它，而 `ai/praat_ai/server.py:312-313` 仍从 `config.server.threads` 取值。应把服务运行参数做成可观测状态并在变化时重启本项目服务；至少验证同模型 4K→16K、视觉开关和线程数。
7. **P1：两个不同目录下的同名模型被误判为同一个。** `ai/praat_ai/server.py:80-91` 只要完整路径不相等，就退化为只比文件名。隔离探针中 `D:/one/model.gguf` 与 `D:/two/model.gguf` 返回 `True`。因此状态可能假报匹配、切换不会重启。只有服务端只上报文件名时才可采用弱匹配；如果双方都有完整路径，应规范化后严格比较。

## 次级缺陷与设计缺口

- **工具调用协议在上限处不完整。** `ai/praat_ai/chat.py:652-777` 达到 `MAX_AGENT_STEPS=5` 后停止处理本轮剩余调用，却仍把该轮 assistant 声明的全部 `tool_calls` 放进下一轮消息（`chat.py:804-825`）。隔离探针一次给六个调用，实际执行和 `role: tool` 回复只有五个，缺 `c5`；随后请求总结时，严格要求调用与回复成对的服务会拒绝请求。上限行为要为每个未执行调用补回“已跳过”结果，或限制转发给服务的调用列表。
- **token 预算只在一轮开头裁一次。** `ai/praat_ai/chat.py:944-1027` 裁历史/对象列表；后续工具观察直接追加在 `chat.py:825-827`，没有再按上下文限额检查。隔离探针让工具返回长输出，第二次请求估算约 20,412 token，配置上限 8,192。真实量纲取决于模型 tokenizer，但“无后续裁剪”是确定的；应给每轮工具结果设置预算并保留可访问的完整结果文件，回归长查询。
- **环境变量专用的 API key 会被保存到文件。** `ai/praat_ai/config.py:334` 读取 `PRAAT_AI_API_KEY` 并写进配置对象，`ai/praat_ai/api_settings.py:126,196-225` 把该值预填并持久化。临时配置加合成 key 的探针确认，即使原配置文件没有 key，仅打开窗口并保存也会把环境变量值写盘。这与“可只放环境变量”的说明不符；保存前应区分文件值和环境覆盖值，界面只显示密钥是否已由环境提供。
- **两个请求字段没有落实。** `minimum_error_duration_sec` 在 `models.py:85`、`tutor.py:57` 中可设置，但评分器 `pronunciation.py:65-143` 没读它；“短于阈值的错误合并/过滤”并未实现。已有 `PhoneSpec.learner_start/end` 在 `pronunciation.py:145-183` 中被强制对齐结果覆盖；调用者手工指定的边界不能保留。先定义手工边界优先级和错误区间语义，再写端到端验收。
- **设计文档阶段二/三仍有缺口。** `docs/ai-frontend/DESIGN.zh-CN.md` 规划“多标准音范本”“音素类别专用特征（如 VOT、闭音段、CPP/HNR）”“已有 TextGrid 直接用边界”“按需卸载服务”“语图/波形/轨迹叠加”。当前纠音入口 `ui.py:39-163` 只选一个标准 Sound，`pronunciation.py:65-143` 对各音素一视同仁遍历通用特征，`report.py:91-166` 只绘制错误特征曲线，`tutor.py:201-202` 仅在卸载延迟等于零时停服务；延迟为 120–600 秒时看不到定时卸载实现。对话工具的 VOT 模板是另一条链，不能替代纠音评分里的塞音 VOT。将这些标为未完成的产品功能，排在核心正确性之后。
- **旧翻译交接要重新定界。** `tools/translation_gap_handoff.md` 日期为 2026-06-14，指向旧工作路径；其中数量是当时的启发式候选，不是当前未译项的实测值。本次不据此声称 UI 翻译有特定缺口；只有 `ai/HANDOFF.md` §6 提到的少量中英混排词条，可在纠音主链稳定后按 `guide.md` 的翻译工作流另行复扫。

## 建议下一步

1. **先救输出和评分可信度。** 写两个会失败的端到端用例：输出 TextGrid 经 Praat 重新读取且报告文件在 Python 运行后仍可打开；同一录音在两侧相同边界下为零错误。修 `PointTier`、回导目录清理与双侧边界，再用真实录音人工核对声谱图。GUI 真机检查 TextGrid、PNG、JSON 三个结果的可见性与路径。
2. **再统一状态变更入口。** 在一个入口处理 API/本地切换、预设运行参数一致性和 PID 所有权。用临时配置与假的服务进程先测状态转换，随后跑 `verify_api_switching_live.py`、`verify_api_dialog_live.py`、`verify_presets_live.py`，明确从菜单独立窗口保存的路径也在测试内。
3. **最后补齐多步执行和产品能力。** 每个改变对象的动作后更新上下文，保证工具调用的请求/回复一一对应，限制每轮工具结果长度。再逐项实现手工 TextGrid/多范本/音素特定评分和实际定时卸载；根据真实录音建立回归数据集。`0.8B` 首轮错选工具是交接文档已确认的模型能力边界，应以 `2B` 或更大模型测功能，不把它与上述确定性代码缺陷混为一谈。
