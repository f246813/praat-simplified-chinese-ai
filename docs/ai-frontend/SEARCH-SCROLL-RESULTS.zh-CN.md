# 搜索结果浏览时刷新修复（2026-10-04）

根因在本项目的 React 接入层：`useSessionSearch` 把完整 `state.sessions`
数组引用当作搜索版本。保存滚动位置、阅读锚点或草稿，以及 Pi 预览预取/
会话读取都会生成新数组。搜索因而进入 loading，清空正文命中的会话 ID，
卸载结果行并重复调用宿主搜索，造成闪动和滚动位置变化。

修复仅调整搜索版本依赖：使用会话 ID、标题、持久化更新时间和归档状态生成
稳定版本，按 ID 排序以排除置顶/分区排序影响。滚动、草稿和未变化的历史读取
保留结果；查询变化、会话增删、改名、真实正文更新和归档变化仍会重新搜索。
既有 Codex 100ms 防抖、代次检查及宿主 SQLite 搜索保持原样，没有引入搜索引擎
或修改滑条与侧栏布局。源码和此修复说明已随正式资产提供。

验证：

- 修复前，阅读位置变化和预览预取的两个回归检查均实际失败：正文命中行变成
  `null`。修复后均通过，会话改名更新结果的检查也通过。
- TypeScript 编译通过；完整前端单元检查 15 个文件、96 项全部通过。
- 浏览器 4 项通过，覆盖搜索结果打开/上下滚动/刷新、IME 输入以及匹配导航复用。
- 正式 pywebview/WebView2：隔离数据库中 80 条正文命中结果，侧栏上下滚动、
  预览预取、刷新未变化会话后，搜索调用仍为首次的 1 次；结果 DOM 节点和侧栏
  滚动位置不变。写入真实新消息并刷新后，搜索调用增为 2 次，新命中会话出现。
  没有模型或 Praat 执行请求。隐藏原生窗口通过 DOM 事件驱动侧栏处理器；消息区
  的真实鼠标滚动由浏览器验证，阅读位置保存由实际 ChatStore 的单元检查验证。
- 正式离线构建通过；当前源码/许可证分发、固定原文件校验及滑条文件不变检查通过。
