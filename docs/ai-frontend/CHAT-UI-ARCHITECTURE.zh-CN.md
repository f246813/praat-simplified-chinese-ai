# 现代 AI 聊天前端：已确认架构与设计

## 1. 状态、范围与文档优先级

- **状态：用户已在 Agent 模式明确授权构建；现代宿主、执行服务、React 前端与离线构建／隔离验收已完成。** 实际结果与未执行项见 [构建结果](BUILD-RESULTS.zh-CN.md)，不以历史测试代替现代前端验收。
- 历史设计整理批准：[现代 AI 前端设计文档整理与新会话构建交接（仅文档）](../../.pi/plan/现代-ai-前端设计文档整理与新会话构建交接-仅文档-20261003-1710.md)。该文件当时仅授权文档整理，本轮构建授权来自用户本次 Agent 指令。
- 本文是现代聊天客户端重构的权威设计；[构建交接](BUILD-HANDOFF.zh-CN.md)保留实施顺序。无单独授权，不调用真实云端、不发布或推送。
- [PI-Desktop 缺口审计](PI-DESKTOP-GAP-AUDIT.zh-CN.md)记录批准交互的落地核对结果、尚未搬入的清单，以及两个会破坏移植的宿主事实（WebView2 私有模式清除浏览器存储、三栏预算常量）。
- [旧专业设计](DESIGN.zh-CN.md)保留专业声学流水线、算法和历史验证；其中旧版“仅本地／禁止云端”等政策不是新聊天架构的要求。涉及本次聊天架构的冲突，以本文为准。
- [历史交接](../../ai/HANDOFF.md)中的执行事实、数据保护与环境注意事项继续作为构建参考；过去的测试通过不表示新前端已经通过。

目标是**完整的现代 AI 聊天客户端界面重构**：引入 AI 行业广泛使用的 assistant 风格聊天、会话侧栏和完整设置页面，而不是继续修补 Tkinter 或只替换一个聊天框。

## 2. 总体架构

### 2.1 已选定方向

| 层 | 已确认选择 | 约束 |
| --- | --- | --- |
| 聊天 UI 主干 | assistant-ui／React | 使用成熟组件和运行时适配接口，不另造完整聊天组件库 |
| 局部交互来源 | PI-Desktop | 批准的局部功能全部纳入，剥离原应用依赖后适配 |
| 桌面承载 | 优先 pywebview＋Windows WebView2 | 实际兼容性、宿主能力、离线资产和打包在实施时验证 |
| Python 执行 | 云端 Pydantic AI／Pydantic Graph、本地模型客户端 | 保留现有执行能力，解除对窗口对象和 Tk 队列的依赖 |
| 专业工具 | Praat 工具桥、声学处理、结构化证据 | 保留专业业务与投递安全，不重写原生算法 |
| 会话与记录 | Python 应用服务＋SQLite | 新会话恢复续聊；旧记录先只读保留 |
| Agent 内核 | **不引入 Pi Agent 内核作为执行运行时** | Pi 模型元数据、预算等局部策略仍可研究或移植 |

前端构建工具链与交付运行时分开说明。React 前端的构建可能需要 Node；“不引入 Pi 内核”不等于“构建阶段不需要 Node”。

遇到 pywebview／WebView2 的具体问题，先核查上游源码、已知问题和修复；不要无依据地更换已确认架构。

### 2.2 职责边界

```text
assistant-ui／React 聊天与设置界面
          ↕ 受限、类型明确的宿主接口与事件
pywebview 桌面壳／Python 应用服务
          ├─ 会话与记录
          ├─ 多会话任务调度
          ├─ 统一模型请求适配
          │    ├─ 云端 Pydantic AI／Graph
          │    └─ 本地模型客户端
          └─ 串行 Praat 工具执行与证据管理
```

- UI 只展示数据、管理交互并发出用户动作，不直接拥有文件执行、API 请求政策或 Praat 授权判定权。
- 消息、进度、思考、工具状态、错误、取消和结果携带会话／任务标识；禁止按当前界面选中的会话推断归属。
- 使用一套聊天状态、消息列表和输入提交系统。持久化／任务服务与 assistant-ui 的显示适配职责明确，不再叠加 PI-Desktop 的完整聊天运行时。
- 保留 Python 能力不等于保留 `chat.py` 中 UI、状态和执行控制混杂的实现，也不等于保留 `cloud_workflow.py` 对窗口对象的直接访问。

### 2.3 不搬入的应用系统

不整套搬入 PI-Desktop 的 `ChatSurface`、完整 `Composer`、全局 `app-store`、Electron／Rust 宿主、preload／IPC、插件系统、子 Agent、Pi 专属计划审批或工作面板。其成熟局部交互可以剥离后使用。

不因为采用某个 UI 样式，宣称已经拥有该应用背后的 Agent、权限、恢复或调度能力。

## 3. 聊天功能：批准范围全部纳入

优先使用 assistant-ui 或其他成熟库已经提供的同等能力，缺失部分再从 PI-Desktop 提取。下表不是可删减的低优先级候选。

| 功能组 | 必须保留的功能与交互 | PI-Desktop 重点参考 |
| --- | --- | --- |
| 输入编辑器 | 富文本输入、中文输入法防误发送、换行、快捷键、输入历史、会话草稿、附件标记及删除 | `ComposerInput.tsx`、`editor.ts`、`native-deletion.ts` 与 composer hooks |
| 思考与执行过程 | 思考折叠／展开、执行过程展示、真实运行状态 | `ActivityGroup.tsx`、`shared` 中的 `ThinkingRow`、相关过程组件 |
| 工具卡片 | 参数／结果、成功／失败等状态、展开详情，适配 Praat 专业内容 | `ToolRow.tsx`、`ToolDetails`、`tool-presentation.ts` |
| 流式正文 | 流式 Markdown、代码高亮、公式／图表、文字释放效果 | `Markdown.tsx`、`useSmoothText` 及其渲染依赖 |
| 滚动与历史 | 自动跟随、上翻停止跟随、回到底部、展开锚定、长历史显示、阅读位置保留 | `useTranscriptScroll.ts`、展开锚定及历史窗口逻辑 |
| 附件交互 | 文件标记、粘贴、拖入、文件选择、预览、附件反馈 | `useComposerAttachments`、附件与预览组件 |

“全部搬入”指完整保留这些功能和交互，不要求原文件未经适配直接复制。可移植局部逻辑或样式，不同时引入两套完整组件系统。

### 3.1 后端真实性与宿主适配

- 思考只显示模型实际提供的内容；工具状态依据真实工具事件；音频能力和压缩提示依据真实结果。
- 不用虚构思考、工具调用、验证成功或压缩完成掩盖后端尚未接通。
- 剥离原组件中的全局 store、插件和工作面板依赖，用本项目的受限动作／数据接口替代。
- 文件选择、拖入文件路径、附件落盘、读取预览和外部链接由宿主适配，不能假设 pywebview 自动兼容 Electron 接口。
- 保留 Markdown 等成熟渲染链路的安全处理；不能为视觉效果绕过内容安全边界。

## 4. 左侧会话记录与设置入口

- 参考 PI-Desktop 和主流 AI／Harness 客户端布局。
- **聊天会话侧栏默认折叠**，保留明确的展开入口。
- **会话侧栏完整交互（2026-10-04 后续已确认并实施）**：PI-Desktop 紧凑列表、独立置顶区、时间分组与折叠、四种排序、悬停预览、菜单、Ctrl/Cmd／Shift 多选、键盘导航与 Ctrl/Cmd+B、侧栏宽度拖动接入现有宿主；历史滚动条贴边并扩大为 14px 命中通道。来源适配和验收见 [会话侧栏移植](PI-SESSION-SIDEBAR-RESULTS.zh-CN.md)。
- 展开后提供新建、搜索、切换、重命名、删除等标准会话操作。
- 各会话保留自己的输入草稿与阅读位置；切换界面不取消原会话任务。
- **设置齿轮固定在会话列表下方的底部区域**，不随历史列表滚动。
- 侧栏展开时显示齿轮＋“设置”；折叠时仍保留齿轮及提示。
- 点击进入完整设置仪表盘，不弹出旧的小型 API 设置窗口。
- 会话历史管理不意味着自动恢复或重放 Praat 操作。
- **窗口内分区尺寸可调（已实施）**：展开的侧栏宽度与对话区列宽都可用指针拖动、键盘步进与双击还原，两处均通过宿主 `settings.preferences`（`sidebar_width`／`conversation_width`）持久化。不写入浏览器存储——WebView2 以 private mode 运行并在关闭时清除用户数据目录。常量、折叠阈值、预算与缺口审计见 [PI-Desktop 缺口审计](PI-DESKTOP-GAP-AUDIT.zh-CN.md)。
- **展开锚定（已实施）**：工具栏与思考卡片的折叠／展开以“该行相对滚动容器顶边的偏移”为锚，行**上方**的高度变化由滚动位置吸收，真实手势解除；实现见 `ai/frontend/src/scroll.ts` 与 `Anchoring.tsx`，常量与反证见缺口审计第 6.2 节。
- **长历史挂载窗口与阅读锚点（已实施，含契约扩展）**：长历史只挂载尾部窗口（首帧 15 / 稳态 60 / 每次 +40），窗口外的行不进 DOM，并提供“显示更早的 N 条消息”。原 `sessions.view` 的像素 `scroll` 在窗口化后不再能表达阅读位置，因此新增 `anchor:{messageId,offset}`：前端取锚、宿主校验并持久化（`sessions` 表增量加列），锚所在行不在窗口里时先撑大窗口再恢复。实现与取舍见缺口审计第 6.5 节。
- **对话缩略图（已实施）**：左侧 dash 导轨给出长历史导航——user 13px／assistant 8px、指针余弦放大、悬停显示该轮预览、点击把该行带到视口顶部 24px 处；只描述**已挂载**的行（挂载窗口外的行没有 DOM），「更早历史」那条虚线展开下一页窗口。见缺口审计第 6.6 节。
- **会话内查找与命中高亮（已实施）**：`Ctrl / ⌘ + K` 打开查找条，命中用 **CSS Custom Highlight API** 绘制（不改写 React 的 DOM），上/下一处把命中带到视口约 1/3 处。可搜索集合是**已渲染的转写**：凡计入的命中都能被高亮与对齐；只在被扣住的行里存在的匹配不计入数字，界面改为提供「显示更早的 N 条消息」动作。见缺口审计第 6.7 节。

采用**左侧分类导航、右侧具体设置和分组卡片**的完整页面。设置页分类导航保持可见，不套用聊天会话侧栏的默认折叠规则。

| 分类 | 主要内容 |
| --- | --- |

| 上下文与输出 | token 三模式、上下文／回复预算、模型能力、压缩相关设置 |
| 采样与思考 | 采样控件、思考档位及模型能力提示 |
| Praat 工具与音频 | 专业工具和音频配置；连接相关音频能力开关仍按下一节完整保留 |
| 外观与交互 | 主题、字体、输入与流式显示等交互设置 |
| 会话与存储 | 会话、历史记录与存储管理 |

同一配置在其他页面提供快捷入口时，仍使用同一存储和请求适配，不形成独立的两份值。

### 5.1 “模型”分类：旧 API 顶部版块完整迁移

依据 `ai/praat_ai/api_settings.py` 的顶部连接版块，全部保留：

| 原选项或动作 | 新页面必须保留的能力 |
| --- | --- |
| 服务商 | 服务商选择、预设填充、自定义填写 |
| API 地址 | 配置 API 端点 |
| 模型名 | 配置请求使用的模型 |
| API Key／显示 | 凭据输入及显示／隐藏 |
| 超时（秒） | 请求超时配置 |
| 锁定云端 API | 禁止从顶部切换到本地模型 |
| 启用 API 时停止本机模型服务 | 保留省显存／切回免重载的选择，但尊重其他任务的资源占用 |
| 允许使用自身知识 | 云端可解释、举例；测量数字仍只能来自工具结果 |
| 启用直接音频输入 | 允许发送原始音频、能力提示及结果反馈 |

“启用 API 时停止本机服务”不得卸载其他会话仍在使用的服务，必须通过资源占用调度执行。

## 6. 参数隔离、模型能力、token 与压缩

### 6.1 参数与请求边界

- 本地／云端参数分开保存；切换时不互相覆盖思考、采样或预算。
- 运行中的任务保留启动时配置与模型绑定，不被另一会话切换模型或修改设置改写。
- 测试连接和正式聊天共用模型／接口适配与请求构造逻辑，测试只使用最小验证输入。
- 不再另走带 Qwen 默认采样参数的独立测试请求路径；音频验证也不能冒充正式聊天能力已完整验证。

### 6.2 三种 token 模式

| 模式 | 已批准行为 |
| --- | --- |
| **自动** | 每个模型记录 `contextWindow`、`maxTokens` 并单独适配，参考／移植 Pi 的模型元数据和预算策略；提供已适配模型列表 |
| **手动** | 酒馆式“上下文 token”与“回复 token 上限”滑条，显示当前数值，用户可调整 |
| **服务商决定** | 项目不额外施加 token 上限；若接口必须填写输出字段，明确呈现该模式的适用性，不静默添加项目上限 |

服务商默认值不等于模型最大能力；省略上限字段不能宣称必然使用模型最大输出。

### 6.3 所有模式统一压缩

- **所有模式都在接近上下文满载时压缩一轮**，按真实模型窗口判断，保留近期消息及结构化专业证据。
- 不用固定窗口或“最近四条、每条截断”冒充完整上下文压缩。
- 压缩改变发送给模型的上下文，不删除用户可查看的原始历史。
- 摘要不能替代工具测量事实；必须保留原任务目标、证据来源、范围和必要执行事实。
- Pi 的压缩策略可作为局部参考，不引入其整个 Agent 运行时。参考策略中的压缩余量不等于所有模型的统一回复上限。

### 6.4 采样与思考

- `temperature`、`top_p`、`presence_penalty` 按已批准的酒馆式控件交互与展示样式实现，均可调节并显示当前数值。
- 当前 `0.1 / 0.8 / 1.5` **未批准为所有模型的统一新默认值**。
- 已有用户配置的迁移、模型默认值和不支持的字段明确区分，不把本次 UI 整理当成更改默认值的授权。
- 思考配置按本地／云端与任务隔离，不能再通过一个 UI 动作同时覆盖两侧参数。

## 7. 会话续聊、历史与存储

- **新会话支持恢复续聊**，持久化足以重建的聊天上下文、摘要和必要元数据。
- **旧 SQLite 记录先只读保留**，不丢失原始记录，不强行转为工作流检查点。
- 现有 `ConversationStore` 保存的是查看记录，不是工作流恢复检查点；新会话的上下文存储需单独设计清楚。
- 不自动重放旧 Praat 操作，恢复对话不等于恢复未完成分析执行。
- 记录继续避免保存 API Key、音频 Base64 等敏感内容；附件内容的存储与记录元数据的职责分开说明。
- 新历史、摘要和必要专业证据的关系明确，不能用摘要覆盖原记录或把模型生成内容升级为测量事实。

## 8. 多会话后台任务与 Praat 串行执行

用户选择的是**支持多会话后台任务**，不是全局单任务。

- 消息流、进度、思考、工具状态、取消和结果归属对应会话／任务。
- 切换界面不取消原任务，也不把后台结果投到新选中的会话。
- 同一会话的提交规则和排队需明确，避免并发写入破坏上下文顺序。
- Praat 工具执行采用**全局串行调度**，绑定原任务的对象与范围，执行前核对有效性；不能误用当前界面选中的对象。
- 串行单位覆盖对象选择、操作及结果读取等不可交错的操作段。只串行单条调用、却让其他任务污染选择状态，不满足要求。
- 取消一个任务不能误取消其他任务；执行状态不明时保留原有保守投递约束，不自动重复提交。
- 本地模型加载、卸载和并发能力按资源占用调度，不承诺小模型服务无限并发；不能因另一个会话切换云端而卸载在用服务。

## 9. 必须保留的专业业务边界

- 工具白名单、结构化参数校验、有限修正、成功证据复用。
- 测量与模型推断分离；测量数字必须来自工具结果。
- 独立报告阶段的执行约束，不在报告阶段随意追加 Praat 操作。
- `delivery.py` 的投递事实：未投递、已投递、执行状态不明、后续投递被阻止。
- UI 的成功、失败、取消状态不能覆盖投递事实；取消不意味着已执行操作被撤销。
- 不因更换 UI 改写 Praat 原生算法，或让模型自由生成专业测量结果。

### 10.2 不重复造轮子的工作规则

1. 遇到问题先检索成熟组件的文档、源码、示例、issue 与既有修复，再决定移植或写最薄适配。
2. 已有同等能力优先复用，不复制整个应用解决局部问题，不无限查阅阻碍实现。
3. 每个直接复制／修改的组件记录来源、固定版本、许可证和本地修改，保持边界可追溯。
4. 本项目开源不等于可以忽略上游许可证；不得把 LGPL／AGPL 代码重新标成 MIT。交互／截图参考与直接复制源码分开记录。
