# 云端 API 桌面启用修复（2026-10-04）

问题：用户已保存并启用云端 API，但 Praat 菜单启动的 `run_ai_chat.py` 没有 `--allow-cloud` 参数。现代宿主仍按隔离测试模式拒绝所有远程模型请求，设置中的测试按钮也被禁用。

修复使用现有配置和调用链：`modern_host.main` 为交互桌面启用 `configured_cloud` 策略。`ModernApplication.prepared` 在每次请求前检查当前候选配置，只放行已启用的 API 端点。前端通过原有 `bootstrap.host.cloudAllowed` 获取宿主能力，无需新增 RPC、前端权限按钮或代理内核。API 保存和启停可以在同一窗口生效；运行中的任务继续使用其配置快照。

启动、读取配置和保存设置均不调用服务商；测试继续使用既有确认弹窗。远程“本地模型”地址、非法协议和地址内嵌凭据仍被拒绝。直接构造隔离服务默认限制云端，显式 `--allow-cloud` 覆盖参数仍保留。

验证：

- 修复前，正常菜单入口回归测试未启用桌面策略而失败；修复后新增 7 项回归测试通过。
- 相关宿主、应用、启动入口共 57 项测试通过。
- 生产前端在真实 WebView2 下通过 4 项验证：桌面测试控件可用、启用保存即时生效、确认后只发送一次模拟验证请求、正常聊天提交走模拟执行器。
- 用户当前配置仅做只读本地检查：API 已启用，端点与服务商预算配置有效；不读取或输出 Key 内容，不调用真实云端，不改变用户会话。

验收记录：[WebView2 结果](verification/cloud-api-activation-desktop-result.json)。测试使用独立临时配置和数据，真实服务商的凭据有效性与模型可用性仍由用户点击测试后的响应判断。

已打开的 AI 窗口仍运行旧的 Python 宿主。保存当前设置后关闭 AI 窗口，再从 Praat 菜单正常打开即可加载修复，不需要运行命令行或重启 Praat。
