# 统一 VOT 分析服务设计

状态：聊天中已确认架构方向，等待用户审阅本规格。

## 目标

让 SoundEditor 的 VOT 窗口和 AI 的 `vot` 工具提交同一份分析请求，经同一个模型对齐与 C++ 声学边界检测流程，并读取同一份版本化结果。模型只负责定位目标音素；VOT 爆破释放和起声边界由 C++ 声学分析确定。缺少可靠证据时返回明确失败或待复核状态，不生成看似精确的单值。

本规格的需求来源是用户在当前对话中的请求及其架构图。仓库内的交接、计划和历史说明仅作为现状参考，不视为新的用户指令。

## 现状

- SoundEditor 直接调用 `praat_Sound_analyseVOT`；AI 的 `vot` 工具生成 Praat 脚本，再调用 C++ VOT 动作。
- MFA 和 wav2vec2 目前存在于 Python `forced_alignment.py`，VOT 两个入口没有调用它们。
- C++ 候选分析先按目标选区裁音频，滤波和音高帧因此缺少前后上下文；当前起声检查还把首个有声帧与选区起点的 10 ms 窗口比较。
- AI 选区解析可把相差不超过 2 ms 的显式时间当作编辑器选区。对齐器没有可用模型时会返回比例估算，双模型结果会加权平均；这些都不能证明 VOT 边界可靠。
- 编辑器目前保存候选与手动输入状态，但模型任务、跨入口请求契约、实际算法回退来源和异步过期处理尚未统一。

## 架构

采用 Python 侧共享 VOT 编排服务，复用现有 MFA/wav2vec2 实现；C++ 保留唯一的声学边界分析实现。SoundEditor 和 AI 工具各自只有输入/显示适配器，均把规范化请求交给同一服务。服务负责输入检查、模型对齐、C++ 分析调用、失败分类与统一结果生成。两入口不得各自实现范围替换、模型选择、候选筛选或有效性判断。

### 请求

`VOTAnalysisRequest` 至少包含：

- 当前音频内容快照、内容摘要、对象 ID 与内容版本、Sound/LongSound 来源、通道数、采样率和原始时间轴起点。
- 采样点形式的目标选择和独立的分析上下文范围。Sound 使用编辑后的当前内容；LongSound 读取与 Sound 相同规则定义的所需上下文。模型使用固定的完整语句或固定上下文；小幅拖选仅用于选择目标音素。
- 语言、已有文字/音素标注、分析模式、算法参数、模型配置，以及唯一请求 ID。

请求内时间以原音频采样点为规范表示。界面秒数只在入口转换一次，并保留采样点与原始时间轴的双向映射。明确的 `from/to` 不得被编辑器选区静默替换；缺少选择和明确范围时不得退回整段录音。

### 对齐和声学分析

- 模型对齐定位目标音素，不能把音素开始/结束直接当成 VOT 两边界。
- 有可用对象标注时共用它。缺少语言或文字/音素时，模型辅助模式给出需补充的信息；用户可明确切换纯声学候选模式。
- 无模型、语言不匹配和对齐失败都返回具体原因。比例分配的区间不得作为模型辅助 VOT 的有效依据。
- 双模型结果分别保留。分歧超过配置阈值时返回歧义/待复核状态，不加权平均为一个边界。MFA 默认置信度不作为校准后的 VOT 可信度。
- C++ 在完整上下文中把滤波、能量和有声分析帧映射回原始采样时间轴；在对齐目标附近联合寻找并配对释放与起声候选。负 VOT 要求目标辅音相关的预浊音证据。多个合理配对、目标不完整或质量不足时不返回单一可用 VOT。
- 结果记录实际模型与版本、模型分歧、算法版本、实际爆破频带/回退路径及原因、参数、边界来源和质量状态。不得仅按采样率推断实际使用路径。

### 统一结果和界面

`VOTAnalysisResult` 至少含请求/快照标识、爆破释放和起声采样点、VOT、候选/手动确认/歧义/失败/过期状态、失败原因、对齐结果与分歧、算法和模型版本、实际检测路径及参数。

三个入口模式一致：模型辅助自动、纯声学候选、人工确认。自动结果始终标为候选；人工确认统一按 `(起声采样点 - 爆破采样点) * 1000 / 采样率` 计算，并保留两个边界来源。分析完成后不自动修改标注；用户点击“应用”才更新。长模型任务后台运行，进度显示在 VOT 窗口。选区、音频内容或请求参数变化时旧结果标为过期；迟到的旧请求不得覆盖新状态。

## 验收标准

验收须分别提供一致性、重复稳定性、选区稳定性和准确性证据。单测或直接调用内部分析函数不能替代完整入口测试。

### 一致性

固定同一音频快照、对象版本、原始时间轴、目标、语言/标注、模式、参数、模型与模型版本。分别通过目标 `Praat.exe` 的完整 VOT 窗口流程和 AI 的完整 `vot` 工具流程提交；比较两边的规范请求和结果。边界采样点、VOT、状态、失败原因、模型/算法来源和检测路径必须一致。不能只比较重新计算的 VOT 公式或内部候选规则。

### 重复稳定性

在禁用结果缓存后，以相同模型、软件和请求至少独立运行 5 次。比较规范化边界、VOT、状态和来源；记录任何模型随机性并通过确定性推理设置消除。缓存命中不得计作重复计算通过。

### 选区稳定性和目标完整性

对完整目标作小幅选区移动，只要仍解析到相同目标音素和固定模型上下文，结果边界应保持在 **5 ms** 误差内（此数值是本规格提出的初始验收阈值，等待用户审阅）。让选区切掉目标的一部分时必须返回 `target_incomplete` 一类明确失败状态，不得给出单一 VOT 数值。覆盖 Sound 和 LongSound，并验证边界时刻仍使用原始时间轴。

### 准确性

以真实录音上的人工边界标注为参照，覆盖日语、正/零/负 VOT、多个爆破候选和持续有声片段。爆破释放与起声分别评分，同时报告有符号 VOT 误差、候选漏检/错配、歧义识别和误报单值情况。标注应由人工独立完成并对分歧作仲裁；此前观察到的 `+14 ms` 不得作为正确答案。用户录音可加入回归集，但只有其独立标注后的边界才是测试真值。若验收环境拿不到录音或标注，报告准确性项未验证，不用仓库里的未标注音频替代。

### 完整入口与窗口行为

- 在指定的 `Praat.exe` 构建中，通过 SoundEditor VOT 窗口完成请求、等待进度、显示候选、编辑并点击应用；验证实际边界更新。
- 通过 AI 前端触发 `vot` 工具完整链路，并读取同一结构化结果。
- 在模型运行期间改变选区/音频/参数，确认旧任务迟到结果被丢弃且旧显示标记过期。
- 明确验证模型缺失、语言不匹配、缺少标注、对齐失败、纯声学候选、模型分歧、C++ 无候选、多个候选和 LongSound 读取失败等状态。

## 未覆盖范围与待确认项

- 本次不改变非 VOT 的 AI 聊天、Windows 动态操作区或菜单布局行为。
- 5 ms 是选区扰动稳定性的初始项目阈值，需用户审阅。准确性分数按人工仲裁真值报告；若要给出整体准确/不准确结论，还需在查看标注结果后确定边界误差的最终通过阈值。
- 模型任务与 Praat/C++ 之间的异步桥接方式在实现计划中落实；无论具体传输机制如何，都必须保持上述单一请求和结果契约，不得为两个入口另造算法路径。
