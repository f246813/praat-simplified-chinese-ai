# 报告核对、救援与传输重试检查

当前职责见 [工具、报告守卫与投递事实](../CURRENT-IMPLEMENTATION.zh-CN.md#工具报告守卫与投递事实)。本页描述可复现检查条件，不使用历史会话或旧通过数证明当前链路正确。

## 离线检查入口

在项目根目录、已安装项目依赖的 Python 环境中执行：

```powershell
$env:PYTHONPATH = 'ai'
python -m unittest discover -s ai/tests -p 'test_report_guards.py'
python -m unittest discover -s ai/tests -p 'test_report_chain_regressions.py'
python -m unittest discover -s ai/tests -p 'test_cloud_protocol.py'
```

这些检查使用隔离夹具和模拟协议；不等于当前供应商端点、实际 Praat 投递和用户材料的验证。核对以下独立边界：

- 对象编号仅引用快照或证据中已有的对象；数字、量纲和测量来源需相应证据。
- VOT 爆破与浊音起始的自由标签、同值不同单位、显式量名、小数和科学记数分别检查。
- 救援只遮罩未通过核对的位置，保留合法同值、对象编号、证据引用和可用正文；救援稿保持未验证状态。
- 引证修复、覆盖整理、推导标注与阻断按稳定规则 ID 计数，不把定位探查重复计为实际动作。
- 传输重试沿异常原因链识别连接/超时；永久 HTTP 错误或仅含“超时”字样的普通文本不能自动归入同一路径。
- SDK 重开 run 恢复待完成请求时保留消息链与总预算，不重复进入已经使用的流节点，也不重复投递工具操作。
- 执行器返回后、消息落库前取消的回答保持非正式状态；任务取消和失败不能被显示为完成。

检查失败后，应同时查看模型请求、结构化草稿、守卫规则与投递事实。报告没有通过核对不等于工具没有执行；有测量证据也不等于原始目标全部完成。
