# AIPraat 云端上下文、技能和缓存验证（2026-10-06）

Python / Pydantic AI 2.52.0 架构保留。对话、规划、报告使用独立原生消息链和统计，共用任务的 AnalysisState、请求/工具预算与 RunUsage。最终 HTTP 规则、工具及输出协议在同阶段保持稳定；动态目标、技能正文、材料和新证据追加到尾部。对话与长历史样本有实测收益；测量报告和失败收尾没有证明加速，不能把本次改造描述为全场景提速。

开源复用：直接使用已锁定 SDK 的 message_history、消息类型/序列化、工具事务、usage 提取与现有 CloudRuntime/SSE 适配；移植 Pi 的内容/工具参数计数和完整事务压缩切点；原样保留 OnlyTerp 的缓存检查脚本及 MIT 许可。没有迁入新的 Agent 框架。SQLite、阶段预算、来源绑定与现有 guard 的连接由项目适配。具体提交、许可和代码对应见 ai/third_party/pi-context/SOURCES.md。开发技能在 .agents/skills/aipraat-prompt-cache；产品只加载 ai/skills。

## 行为和最终请求验证

237 项关键回归通过，覆盖 cloud/dialogue 协议、SSE、ModernApp/Executor、归档删除、L0–L4、报告和工具 guard、投递状态、取消、时长零请求快路、预算与交付规则。新增边界验证包括：

- 三轮真实 SDK/localhost 对话，前一请求 messages 是后一请求的完整前缀，六个原生角色按序追加；三轮共用一个 TCP 连接。
- 同一任务交替规划/报告六次 HTTP 请求，各阶段静态指纹分别恒定，历史分别追加；规划与报告指纹不同。
- SDK 报告校验生成的 RetryPromptPart 在输出额度 400 后保留；新 run 从待处理请求继续，原目标只出现一次。
- 不支持音频时，纯文本降级请求确实没有 input_audio；先前完成的文本链保留，累计预算不变，报告通过校验。
- 压缩只切完整 user-start 事务，保留近期配对工具调用/返回及完整证据；失败、停滞、工具次数、未知投递事实不变，摘要占用一次共享请求预算。
- 会话摘要的请求及 input/output token 初始化到 SDK RunUsage；对话前后预检都排除不会实际发送的执行日志。
- SQLite 消息协议/epoch 可恢复；配置变化保留正式历史；取消/未校验草稿不变成正式回答；音频字节不进入恢复链。
- 原始附件显示名优先于 UUID/临时导出名。仅无词典、无用户说明且名称明确时给出“根据文件名推测”的线索；通用名、练习标签和歧义名不猜。同一录音的用户纠正可保留，换录音不串线；线索不增加证据或开启音频能力。
- usage 缺失保持 null；inclusive 输入不重复加缓存；exclusive 输入有明确归一口径；兼容嵌套 cache_creation_input_tokens。

安装包选取规则已验证包含三个运行时 skill、新 Python 模块和第三方许可；开发 skill 不进入运行时目录。本次更新的是后端源码与安装包构建清单，运行中的 Python 后端需重启后载入。

## 真实 A/B 方法

A 使用 backups/pi-context-cache-20261006/praat_ai 的改造前快照，B 使用当前源码；同一 qwen3.7-flash、dashscope.aliyuncs.com 北京端点、32,768 上下文、4,096 总输出上限。正式样本两边均关闭思考，温度等其他配置相同；每组每版三轮，重复两次，第一轮 A→B，第二轮 B→A。只改变测试配置，用户配置文件未改。总共 20 个正式样本。

隐式缓存冷/热状态无法控制；没有预热或保活请求。连续调用无额外固定等待，实际请求耗时保存在 wire.seconds 中；不把相邻 A/B 当作公平冷启动。HTTP payload 翻译后采集规则/消息哈希、请求字节、usage 和耗时，不保存请求正文、密钥或音频。

测量与语调报告使用 test/fon/examples/sounds/aaaa02.wav，经真实 Praat 批处理产生相同的完整范围数据。规划调用的不确定性在该 suite 中被隔离：预置真实证据后走 L2 报告，工具执行时间不单独对比；完整规划/执行行为由上述回归和最终 HTTP 验证覆盖。失败组预置未投递的依赖失败事实，不把失败当测量。这里只证明这些阶段的观测结果，不声称完成了整条真实 Agent 工具链的性能验收。

旧版经校验的 partial 报告同样加入正式历史；未经校验的草稿两边都不重放。该口径修正后的失败组四个样本替换了初版数据，原记录另存。高思考试跑和输出上限不一致的试跑均单列排除；高思考/4,096 上限的测量报告多次耗尽推理额度，不能据此承诺当前默认 high 设置提速。

## 分阶段和费用口径

对话组仅 dialogue；测量/语调/失败组仅 report。长历史组：A dialogue 输入/缓存读 19,641/9,216、summary 27,830/13,696；B dialogue 18,422/8,448、summary 27,280/13,440。生产 request_timings 和 phases 分开记录 dialogue/planner/report/summary、模式、任务/会话、epoch、请求/重试、首字、耗时、cache read/write、总输入及原 usage 字段名；工具执行耗时另记 tool_seconds。统计不参与模型上下文。

按测试当天官方北京 qwen3.7-flash、单请求 ≤32K 的公开价，未缓存输入 0.2 元/百万 token，输出 0.8 元/百万；隐式缓存读取按输入单价的 20%。公式：`(input_total - cache_read) × 0.2 / 1e6 + cache_read × 0.04 / 1e6 + output × 0.8 / 1e6`。这是实测 usage 的公开价估算，未核对账户账单、免费额度或商业折扣。[模型价格](https://help.aliyun.com/en/model-studio/model-pricing)、[缓存计费](https://help.aliyun.com/zh/model-studio/context-cache)。
