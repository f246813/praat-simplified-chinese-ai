# 菜单文字与圆点重绘修复

## 原因与修改

模型、状态和显存项原来创建时均带 `GuiMenu_INSENSITIVE`，所以 Windows 将三项文字画成灰色。模型和状态改为正常菜单项，保留空回调；显存项根据采样器明确提供的 `frontend_local` 字段切换启用状态：本地模式黑色，API 模式灰色。

原圆点在原生菜单 `WM_PAINT` 后绘制，而 Windows 的悬停选中可以直接重绘行、不触发 `WM_PAINT`。实机复现：本地模式初次打开有绿色点，悬停后像素数为零，重开再次出现。本轮隔离测试没有复现 API 模式出现圆点，但覆盖了 API 连续重开和本地切回 API 的情况。

修复在 `WM_MENUSELECT` 后安排完整菜单重绘，补齐鼠标和键盘选中变化后的圆点绘制。零颜色状态仍注册该状态项，使菜单重新打开时重新绘制干净内容；菜单关闭时解除 subclass 并清空旧窗口绑定。原生侧还依据模式字段禁止 API 绘制颜色，避免使用旧的 GPU 颜色值。

保留原生菜单文字测量和布局，没有引入 owner-draw 行、额外菜单层或位图列。圆点仍在文字右侧。

## 检索与复用

修改前通过 GitHub 插件检索了 Windows 菜单 subclass、WM_INITMENUPOPUP、WM_PRINTCLIENT、WM_DRAWITEM/WM_MEASUREITEM；检索了 Microsoft Windows-classic-samples 的菜单示例，也查询了 Wine 的菜单选择实现。未找到适合直接拼入当前 Praat 原生菜单的独立组件。本次复用项目已有 GuiThing_setSensitive、原生菜单状态 API、圆点颜色/位置绘制及 Windows 消息分发，没有复制新增第三方代码或引入依赖，沿用现有文件 GPL 许可。
