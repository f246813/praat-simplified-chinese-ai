# 前端临时目录修复验收（2026-10-02）

本轮修复“启动前端”时报 `filesystem error: in create_directories`。已修改原生 Python 启动入口，重编译并同步根目录 `Praat.exe`，重新构建 `AIPraat-install.exe`，核对安装器内嵌载荷。

## 原因与修改

报错进程 PID 23636 的完整性 RID 为 4096（Low），非 AppContainer，启动时间为 2026-10-02 14:48:54。它不能写入普通 `C:\Users\f2468\AppData\Local\Temp`。原代码无条件在 TEMP 创建工作目录，因此收到 Win32 错误 5（拒绝访问）。磁盘空间充足，文件 ACL 的完全控制不能绕过完整性限制。

新增 `sys/praat_python_workspace.h`：查询进程完整性，Low 进程通过 Windows Known Folder API 获取 LocalLow，在 `LocalLow/Praat/Python/praat_py_workspace_<PID>` 创建目录；普通进程继续使用标准 TEMP。路径保留 Unicode，未降低 TEMP 的完整性或提升 Praat 权限。查询前用 RAII 初始化 COM，成功调用平衡释放；已有另一种 apartment 时保留原状态。依据：[Microsoft Known Folders 文档](https://learn.microsoft.com/en-us/windows/win32/shell/known-folders)。Token 句柄和返回内存也由 RAII 释放。

`sys/praat_python.cpp` 的脚本文件与脚本文本入口共用该目录函数。Makefile 的 Windows GCC / Clang 链接项增加 `advapi32`、`uuid`。`installer/verification/build-python-workspace.ps1` 重新编译 Python 启动对象，基于此前已发布版本的库重链接完整 Praat；没有重编译其他声学算法库。构建报告同时记录候选、原版本及三个原生源文件的哈希。
