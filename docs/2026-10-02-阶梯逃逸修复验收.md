## 修复结果

| 原问题 | 当前行为与回归证据 |
|---|---|
| 成功测量后的音频证据缺口不自动进入 L3 | 报告用 `missing_evidence` 标记音频/测量/参照缺口。无限制、能力开启、材料可用且预算足够时，最多补一次 L3，沿用当前请求总账。参照缺口、有限模式、能力关闭、快照丢失和预算不足不自动上传。失败时保留有效 L2 报告。 |
| 继续丢失音频观察和上一份报告 | 保留前轮报告、覆盖项、退出原因以及带模型/源文件/范围/指纹的 `model_audio` 定性观察。继续解释已有观察不重传音频、不再调用 Praat 工具。请求副本按容量摘录并去重，完整记录仍保留。 |
| 校验失败掩盖实际音频输入 | 分别记录请求尝试 `audio_input`、模型响应确认 `audio_response_received`、报告通过校验 `audio_report_completed`。两次无效 JSON 仍记录已尝试和已收到响应；明确拒绝或传输失败记录尝试，不能视为响应确认。输入尝试不等于服务器必然接收。 |
| 授权重命名后的保存被拒绝 | 应用确认成功后刷新 Praat 元数据，只采纳同 ID/class 的名称变化，沿用原进程检查和原选区。新建→重命名→保存也保留三个成功操作记录。外部改名、对象消失或 class 改变继续被拒绝。 |
| 网络重试阻止首次重命名 | 实际请求和逻辑规划轮次分开计数。传输重试仍消耗总预算，但不算追加操作；首次授权重命名可执行，后轮未授权变更仍被阻止。 |
| 无证据时一般继续重新执行工具 | 按钮传入显式 L2/L3/L4 模式；一般讨论直接进入 L4，与证据是否为空无关。容量预检按实际模式和方向计入历史对话，容量不足时不提交。 |
| 音频输出错误误关输入 | 输出、生成、TTS、英文进行时及中文动词在前的错误不推断输入不支持。混合“输出不支持/输入支持”也不纠正；包含明确输入拒绝的错误才允许持久纠正。 |

新增回归位于 `ai/tests/test_staircase_review_fixes.py`，共 20 项，覆盖原七项以及边界场景。红灯日志保留在 `installer/verification/staircase-review-fixes-red.log` 和后续 `*-red.log`；首次旧实现 11 项测试中出现 10 个失败（含同一测试的三个分类子场景）。随后各根因修复并通过绿灯验证。

## 独立复核

按 `superpowers:requesting-code-review` 发起一次无会话历史的只读审查。独立审查发现的三个 Important 已修复：混合输入/输出错误分类、小上下文续接摘要及一般讨论预检、新建对象重命名后的绑定刷新。审查代理重跑各自复现以及 54 项相关测试、五项关键测试，最终结论：**当前修复范围没有剩余已确认的 Critical 或 Important，可进入构建和安装包验收。**

复验包含：真实 SDK FunctionModel 返回约 1100 字 L3 报告后，在 4096 上下文/1500 回复预算下继续 L2，发一次文字请求并保留完整原观察；L4 容量不够时不提交、允许时发一次文字请求；新建→重命名→保存投递三个脚本并记录三个成功操作。

审查不修改源码、配置和二进制，不调用真实供应商，不操作用户 Praat。真实供应商兼容性、语音学结论准确度、同 ID/class/name 原地波形编辑识别和原有首响应多工具授权规则未在本轮作新增判断。
