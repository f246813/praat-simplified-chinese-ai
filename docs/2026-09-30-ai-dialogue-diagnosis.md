## 确认的问题

### 1. 工具参数错误与重复检测妨碍纠错

`qwen.extract_tool_actions` 将非法 JSON 转换成 `arguments={}` 并另加 `invalid_arguments`；随后 `assistant_tool_message` 只把 `{}` 作为参数发回模型，丢掉原始非法参数。模型看到的调用变成合法空对象，工具观察却说它不是合法 JSON。

`chat._action_signature` 只包含工具名及解析后的 arguments，不包含 invalid_arguments。不同的非法参数及合法空参数可能产生同一个重复签名。重复分支仍占用规划轮次，但不执行新的纠错尝试。

离线复现确认：非法调用与合法 `{}` 的签名相同；连续八轮相同非法调用只执行一次拒绝，其余七轮被跳过。本次现场确认出现非法 JSON 和重复跳过；八轮复现是代码行为验证，不是现场跳过次数。

### 2. 收尾阶段没有明确结束规划的指令

API 一轮最多 8 次规划、20 次实际工具操作，与是否限制 token 无关。达到上限后的 `_NativePlanner.wrap_up` 直接使用原 messages 发起一次不带工具的请求，没有追加“结束规划、依据已有结果回答原始目标、说明未完成部分”的指令。

离线捕获确认，收尾消息序列最后仍是 `role=tool`。关闭工具只能阻止结构化调用，不能保证模型从“还需要继续测量”的状态转为最终解释。若收尾无可显示正文，`_summary_of` 会输出数据列表和“模型这次没有给出说明”。当前窗口最终回答正是这个分支的产物。

### 3. 有测量结果就返回，缺少目标完成检查

系统提示词确实要求先测量再解释、提供实际结论和未完成部分，但程序没有验证最终回答是否交付用户要求的对比和不足分析。保留数据的兜底防止结果丢失，却没有完成分析任务。

`process_message` 还会在摘要后追加相同的结果，导致最近一次回答中的数据重复。这种重复来自前端拼接，不等于又执行了一遍测量。

### 4. 工具说明、参数 schema 和实际默认值不一致

formant_statistics 的工具 signature 写“默认 1”，但 `_formant_numbers` 的实际默认值是 2。schema 把 formant 定义为 integer，说明却允许字符串 "1,2"；构建器也接受多个编号。

离线渲染确认，不填 formant 时脚本执行 `Get mean: 2`；现场第 5 轮也只得到 F2。这一不一致会增加规划误解；没有原始错误参数，不能断言它就是本次非法 JSON 的直接原因。

### 5. 分析输入没有达到逐音素对比所需的粒度

当前聊天链路向模型发送对象元数据和工具文本结果，没有把音频作为模型输入。最近一次留下的是整个选区的 F0、强度和 F2 统计，没有逐音素边界、逐元音 F1/F2、辅音证据或实际参照录音。

这些数据不足以直接交付具体音素的发音不足判断。开放知识提示允许模型用一般知识解释参照，但仍应明确证据不足，并提出必要的分段测量或参照需求。最终摘要没有做这一步。

## 前两次突然结束：能确认和不能确认的部分

关闭 token 限制时，客户端不发送 max_tokens；离线捕获已确认。但前端的轮数、工具步数上限仍然存在，服务端是否另有输出上限也没有记录。

“重复规划、输出继续分析的文字后结束”与上述纠错及收尾问题相符，但没有前两次原始 content、reasoning_content、finish_reason、usage 和错误记录，不能确定是服务端截断、自然结束、收尾格式问题还是网络错误。当前输出 1500 的配置不能作为前两次截断的证据。

程序直接显示非空 content；reasoning_content 则只接受带明确最终答案标记的尾部。缺少前两次原始响应，无法确认用户看到的思维链来自哪个字段。

## 日志缺失与后续修复顺序

`ChatWindow.history` 只保存在内存；启动器丢弃 stdout/stderr；每次执行脚本前清除共享结果文件。commands 目录只保留有限数量脚本，不能用来完整审计对话。

建议依次修复：

1. 保存脱敏逐轮日志：原始用户请求、实际发送提示、模型 content/reasoning_content、原始工具参数、执行结果、finish_reason、usage、错误和最终回答；不记录 API 密钥。
2. 保留非法调用的原始参数及错误类型，避免把不同非法调用都合并为 `{}`；重复失败应转入明确的纠错或结束流程。
3. 增加明确收尾指令，并区分“测量成功”“用户分析目标完成”“分析未完成”。
4. 统一工具 schema、说明和默认值；对发音比较建立分段证据流程。
