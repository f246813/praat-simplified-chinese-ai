# 本地模型 Message.txt 权限修复

切换本地模型后，现代执行器查询 Praat 最新对象状态时，在投递之前无法写入 `%APPDATA%/Praat/Message.txt`。文件没有只读属性，用户有完全控制权限；真实运行的 Praat（19308）与对话前端（15940）令牌却均为 Low（0x1000）。

本次交付的新可执行文件继承了工作目录的 Low 完整性标签，遗漏了 2026-10-02 已记录的逐文件 Medium 修复。API 对话可不投递 Praat 脚本，因此权限问题会在本地任务状态查询时暴露；模型配置不是根因。

已将 `Praat.exe`、`Praat-model-settings.exe` 和用户正在使用的 `Praat-menu-fixed.exe` 文件标签设为 Medium。没有修改目录、Message.txt 权限或产品源码，也没有降低消息文件保护。备份标签和原始构建脚本位于 `backups/message-permissions-20261005`。

新增 `installer/verification/set-praat-integrity.ps1`，复用既有逐文件 icacls 修复。最新构建脚本自动标记构建产物；加 `-Deliver` 时复制到最终两个入口并再次标记，防止复制后继承目录 Low 标签。

验证采用真实 Praat 批处理启动与 Python 子进程继承链。探针只以 `r+b` 打开消息文件检查写访问，不写字节、不投递脚本给用户会话、不加载用户模型。

- 修复前，三个入口的 Python 子进程均为 0x1000，同样返回 Errno 13。
- 修复后，三个入口的 Python 子进程均为 0x2000，写访问检查全部通过。
- 记录：`installer/verification/message-permissions-before.json`、`message-permissions-after.json`。
- 三个程序的 SHA256、用户配置、对象快照和 Message.txt 内容均保持不变，见 `message-permissions-preserved.json`。构建脚本语法检查通过。没有重新编译二进制，因为修复仅涉及 Windows 文件安全标签。

GitHub 插件已检索 mhammond/pywin32 的 TokenIntegrityLevel/GetTokenInformation 实现（win32/src/win32security.i）。本次未复制外部产品代码或新增依赖；修复复用项目已有 Windows 标签命令，诊断探针按 Win32 令牌 API 编写，无新增第三方许可内容。

当前已运行进程的令牌不能通过修改映像文件标签更新。已保留用户 Praat 与对话窗口，未强制关闭、未重新发送失败任务。使用者需要保存工作，关闭旧 Praat 和 AI 对话窗口，再启动修复后的 `Praat.exe` 或 `Praat-model-settings.exe`，打开前端后刷新状态并重新发起任务。
