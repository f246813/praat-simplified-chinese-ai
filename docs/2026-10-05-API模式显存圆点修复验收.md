# API 模式显存圆点修复

## 原因与修改

状态采样器 `ai/praat_ai/frontend_status.py` 原先在 API 模式下也将本机 GPU 剩余显存转换为红、黄、绿预警。实际旧程序截图复现 API 菜单首次打开时出现绿色圆点（79 个颜色像素）。鼠标移入触发原生菜单局部重绘后圆点被擦掉，但状态记录仍包含颜色，重新打开再次绘制。

修复在状态数据源完成：API 模式不提供本机 GPU 预警颜色，返回 `vram_warning=unknown`、`vram_free_gb=null`。原生菜单收到无预警状态后删除圆点绘制记录并重绘；本地模式保持原有阈值和文字布局。此次无需修改或重编译 C++，现有 Praat.exe / Praat-menu-fixed.exe 每次后台采样会重新读取修正的 Python 模块，等待一次状态刷新即可生效。

## 验证

- 修复前新增回归测试：API 模式的六种显存输入全部失败，确认状态源错误；真实菜单首次打开也检测到绿色圆点并失败。修复前报告和截图保存在 `backups/api-vram-dot-20261005`。
- 修复后 10 个真实菜单检查通过：API 连续三次打开、三次悬停均没有圆点；切到本地恢复圆点；在同一打开的菜单里从本地切到 API 清除圆点，悬停和再次打开仍无圆点。
- 9 个本地模式菜单布局、三色圆点、刷新和单层菜单检查通过。
- 19 个 Python 状态与词典回归测试通过，包含 API 无圆点数据与切回本地的恢复逻辑，以及本地显存阈值边界。
- 用户配置文件 SHA256 保持 `E8765980F914105F18C2C5EDE29F3CE231C4A2F1CE123621C56D25153540F560`。
- 真实菜单报告：`installer/verification/api-vram-menu.json`；布局报告：`installer/verification/frontend-menu-layout.json`。
