# 2026-10-06 对话守卫（prompt→guard）把对话搞坏的修复与验收

用户报：「改后端逻辑把部分提示词转成了几个 guard，结果把对话搞坏了」。
本文件记录现场、根因、改动和验证边界。**只改 Python（`ai/praat_ai/*.py` 与测试），
没有动 C++、没有重编 `Praat.exe`、没有调用云端、没有改用户配置。**

## 1. 现场：最近一次对话两轮都只有「阶段记录」

数据来源：`ai/runtime/modern/sessions.sqlite3`（当前 WebView 前端用的库）。库里只有
一条会话 `d428eea02b534061858c861459eada2e`，两轮：

| 轮 | 用户 | 助手实际返回 | 状态 |
| --- | --- | --- | --- |
| 1 | `计算VOT` | 「原始目标：计算VOT／**本轮仅交付阶段记录，目标分析尚未完成**」 | partial |
| 2 | `与标准音对比，指出不足之处与改进建议` | 同一套模板 | partial |

第 1 轮的真实情况是 **`vot` 工具已经成功交付**（`VOT 估计值 = 0.0380 秒（38.0 毫秒）`），
第 2 轮 `object_info` / `duration` / `pitch_statistics` / `formant_statistics` 四个工具也都成功。
用户看不到任何结论，是因为两轮的 `state.reason` 都让报告阶段走进了
`escape_policy.AnalysisState.fallback_report()`：

- 第 1 轮：`Exceeded maximum output retries (1)`
- 第 2 轮：`JSON Schema 校验失败：'f1,f2,f3' is not one of […]；Exceeded maximum output retries (1)`

改动前的代码版本可从 `backups/native-hooks-20261005/`（10/5 14:40）对比出来：`tool_guards.py`
与 `report_guards.py` 都是 10/5 14:48 新增，`cloud_agent.py` 的内联校验被搬进 pydantic-ai
原生 Hooks，并在报告阶段加了 `Hooks(after_output_process=validate_report)`。

## 2. 根因

### 2.1 `measure` 的 schema 与自己的说明书矛盾（第 2 轮的直接原因）

`tools._measure_schema()` 把 `parameter` 写成**单个** `enum`，而同一文件的
`summary`、`measure_signature()`、`_measure_names()` 都明确写着「一次可以写多个（逗号隔开），
例如 `"f1,f2"`」。模型按说明书传 `f1,f2,f3`，`ToolGuards.normalize()` 的
`Draft202012Validator` 判非法 → `ToolError` → `state.failed()` 两振出局 → `BranchExit`
终止整个工具阶段（`escape_policy.py:99`）。

### 2.2 报告守卫的「量名」比对按字符串相等，换个说法就判成编造（第 1 轮的直接原因）

`report_guards._role()` 在证据侧只要 `tool == 'vot'` 就把整行数字一律打成 `vot.value`，
声明侧却从模型句子里取自由标签（`爆破`、`浊音起始`…）。改动前实测：

```
claim-side role('爆破 ') = '爆破'      evidence-side = 'vot.value'
[PASS]   VOT 爆破 0.551 秒 [E1]
[REJECT] 爆破 0.551 秒 [E1]        -> 数值“0.551 秒”未匹配同对象/范围/量名的测量
[REJECT] 爆破在 0.551 秒 [E1]      -> 同上
```

也就是说：只有把证据原文的「VOT」重复写在每个数字旁边才可能过。报告 agent 当时只有
一次 output 重试，两次被拒就抛 `UnexpectedModelBehavior('Exceeded maximum output retries (1)')`，
整份回答被换成阶段记录。

### 2.3 放大器

- 报告守卫失败 = 丢答案：`fallback_report()` 产出的是元信息，用户读到就是「对话坏了」。
- 执行前被挡下的**提案错误**（参数写法、参数组合）和**执行失败**共用一个两振出局计数器。
- `measure` 的第二个坑：把专用工具的参数混进一次 `measure`（`hl_ratio`、`intensity_slope`
  等）也属于执行前错误，同样会两振出局。

## 3. 改动

| 文件 | 改动 |
| --- | --- |
| `praat_ai/tools.py` | `parameter` 的 `enum` 换成由参数表生成的 `pattern`（单个或多个，`,`/`，`/`、`/`;` 分隔），仍拦得住拼错的名字；分隔符抽成 `MEASURE_SEPARATORS`，`_measure_names()` 与 schema 同源 |
| `praat_ai/tool_guards.py` | 新增 `ToolGuards.parameter()`：先按参数表逐个校验并规范化（不认识的名字报中文可用清单），再交 schema；新增 `SchemaViolation`；**执行前挡下的提案错误不再记 `state.failed()`**（`BranchExit` 仍照常抛出），重复次数由 pydantic-ai 工具重试上限、相同提案跳过、本轮工具预算兜住 |
| `praat_ai/report_guards.py` | 新增 `_free_label()` 与 `rejected_values()`：声明侧**没有点名量名**（只有「爆破」「浊音起始」这类出处标签）时，退回「同对象 + 同范围 + 同量纲 + 同数值」核对；点名了量名（基频/共振峰/强度/VOT/时长…）仍走原来的严格规则 |
| `praat_ai/cloud_agent.py` | 新增 `rescued_report()`：守卫拒绝时保留模型草稿，把没核上的数值（从守卫理由里取回）替换为 `[未通过核对的数值]`、内部 `{{calc:…}}` 替换为占位说明，并在末尾注明未通过核对；没有草稿才回退阶段记录。工具阶段重试 `{'tools':1}` → `{'tools':2}`；报告阶段**保持** `{'output':1}`（带音频时每次重试都要重发音频，不值当） |

### 关键取舍

- **没有放弃「不许把没测过的数字当结论」**：保留正文的同时把没核上的数值遮掉，
  `test_report_failure_keeps_real_evidence_and_discards_fabricated_output` 仍然要求
  报告里不出现 `999 Hz`。
- **守卫本身没有被删**：改的是它「怎么认定同一个量」和「拒了之后怎么办」，不是放宽到不检查。
- 自由标签兜底会接受「同对象同范围同量纲同数值」的任意标签。代价是极小概率把同一行里
  另一个真值当成该标签的值；收益是证据换个说法不再被当成编造。

## 4. 验证

- 探针脚本 `_diag/verify_guard_fixes.py`（不联网、不启动 Praat）：schema 接受 `f1,f2`/`f1，f2`/
  `f1、f2`/`f1; f2`、仍拒 `f1x`；`normalize` 归一为规范写法；VOT 行的「爆破 0.551 秒 [E1]」通过而
  `0.777 秒`、无引证、单位不对仍被拒；「F1 冒充平均基频」仍被拒；草稿保留 + 数值遮罩；
  **按损坏会话里那次 33 参数的 `measure` 调用原样重放**：不再被 schema 判非法，随后按产品规则
  提示「拆分专用工具」，且不写进 `failures`。
- 新增回归：`test_measures.py`（schema 覆盖每个参数、接受说明书里的多参数写法）、
  `test_tool_guards.py`（多参数 measure 走通、参数笔误不再暂停分支、守卫拒绝保留草稿）、
  `test_report_guards.py`（VOT 组件换说法通过、编造/无引证仍拒）。
- 完整套件：见 §5 记录。已知与本改动无关的环境性失败：`test_cloud_protocol` 4 条
  （本机 `NO_PROXY` 里 `[::1]` 让 `httpx2` 构造客户端抛 `Invalid port`，历史交接里已记录）。

## 6. 边界与未做

- 报告守卫对「具体录音的音调/走向结论」仍要求同目标且有定义值的走向证据（平均值不足），
  这条没有放宽：它拦的是结论，不是数字。
- **改完 `ai/praat_ai/*.py` 必须关掉对话窗口重开**，否则跑的还是内存里的旧代码。
- 本次没有调用真实云端、没有用真实录音重跑那两句原话；那需要用户自己的 API 额度。
- 回退点：`backups/guard-fix-20261006-0045/`（改动前的 `tools.py` / `tool_guards.py` /
  `report_guards.py` / `cloud_agent.py` / `escape_policy.py`）。
