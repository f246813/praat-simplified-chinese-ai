# AI 前端输入法组合文本修复（2026-10-01）

## 原因及证据

中文拼音、日语假名等尚未确认的文字由 Windows 输入法组合窗口绘制，并不直接由 Tk Text 绘制。

修复前，实际检测到前端进程 DPI awareness 为 0（不感知 DPI），Tk 以约 96 DPI 绘制，Windows 在本机 125% 缩放下放大窗口位图。输入框字体为 Microsoft YaHei UI、10 point；原生输入法上下文仍保存 System、正高度 16、字重 700。这导致组合文本和已输入文字的字体、尺寸及清晰度不一致。Tk 8.6 的 `Tk_SetCaretPos` 同步了组合窗口位置，但没有调用 `ImmSetCompositionFontW` 同步字体。

Microsoft 要求应用为输入法设置合适的组合字体：[ImmSetCompositionFontW](https://learn.microsoft.com/en-us/windows/win32/api/immdev/nf-immdev-immsetcompositionfontw)。DPI 模式必须在创建 HWND 前设置：[进程 DPI 设置](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)。

## 修改

- 新增 `ai/praat_ai/ui_windows.py`，在首次创建 Tk 窗口前启用 System DPI Aware，保留宿主已经指定的 DPI 模式。Tk 8.6 使用单一屏幕缩放，因此本次采用系统 DPI 模式。
- 所有前端根窗口统一使用 `create_root`，覆盖 AI 对话、独立 API 配置、纠音表单和安装版启动进度窗口。聊天窗口初始尺寸和最小尺寸随主题缩放。
- 对 Text、Entry、ttk.Entry、可编辑 ttk.Combobox 的焦点、按键、点击和当前焦点控件的尺寸变化同步 Unicode 组合字体。保留原 Tk 事件脚本；同步回调先于可能 `break` 的 Entry 类脚本执行。后台控件的 Configure 不覆盖当前输入法字体。
- 正 point 字号只按 Tk scaling 换算一次，负 pixel 字号保留原像素数，同时同步字体家族、粗体、斜体、下划线与删除线；采用 DEFAULT_CHARSET 和 ClearType。没有按语言硬编码字体或字符集，因此中文、日语、韩语采用相同路径。
- 通过原生 GCS_COMPSTR 判断正在组合的文字；此时回车与 Shift+回车不执行发送或额外换行。已完成组合后保持普通回车发送、Shift+回车换行。
- HWND/HIMC 均使用指针宽度类型，获取的输入上下文通过 finally 释放。

## 验证

`ai/tests/test_ime.py` 在独立进程的实际原生输入法上下文中，检查已安装的中文（0804）和日语（0411）布局，在 100%、125%、150%、200% Tk scaling 下，对四类输入控件使用 10/12 point 和 -18 pixel 字号，检查实际组合字体、像素高度、字重、字符集和字体质量。也检查前端实际 DPI awareness 与初始窗口尺寸。未安装相应布局的测试机显式跳过对应原生布局检查。

`ai/tests/test_ime_keys.py` 覆盖中文、日语、韩语预编辑字节长度，以及空组合、原生错误、无上下文和非 Windows 情况的回车行为；这部分通过替身模拟 IMM API 边界。韩语未做已安装原生布局检查。本次没有进行人工候选词面板操作或第三方输入法的目测验收。

修复前字体及 DPI 原生回归均失败，见根目录 `verify-ime-red.log`。修复后 7 项输入法回归通过，见 `verify-ime-green.log`。完整前端测试 648 项通过，见 `verify-ime-all-tests.log`。测试环境原来缺少 parselmouth，已按项目 requirements 将 0.4.7 安装到隔离的 `.build-tools/ime-test-deps`，未修改全局 Python 环境。

复现完整验证命令（PowerShell，项目根目录）：

```powershell
$env:PYTHONPATH = 'ai;.build-tools/ime-test-deps'
$env:PYTHONIOENCODING = 'utf-8'
python -m unittest discover -s ai/tests -p 'test_*.py' -v
```

已运行 `installer/build.ps1` 重建根目录 `AIPraat-install.exe`，并逐字节核对 payload.zip 中的五个修复文件与当前源文件相同。旧源文件与发行文件位于 `backups/ime-before-fix-20261001`。

## 生效方式

当前目录：关闭 AI 对话窗口，再从 Praat 菜单打开。前端 Python 进程需要重新创建窗口才能采用新的 DPI 设置。

安装版：使用本次重建的安装包更新安装目录，再重新打开 AI 对话窗口。用户配置沿用原安装更新逻辑。
