# 前端菜单圆点与布局修复

交付程序：Praat.exe、Praat-menu-fixed.exe；当前运行的 Praat-frontend-status.exe（PID 7248）保持运行。

## 修复

- 显存圆点位于“显存预警”文字右侧。红、黄、绿阈值沿用先前实现。
- 移除显存项的 MFT_OWNERDRAW 和自定义测量。实际对比发现，混入自绘项会改变整张弹出菜单的字体缩放、行高、宽度与文字位置，因此仅调整自绘缩进不够。
- 全部菜单文字、间距、勾选和禁用状态由原生菜单绘制。圆点在该菜单窗口的右侧状态位置绘制；没有创建第二个菜单或额外浮动窗口。
- 字符串更新改用 SetMenuItemInfoW 的 MIIM_STRING，保留状态与类型；内容未变化时不重写菜单，移除周期刷新时普通项/自绘项之间的切换。
- 使用本项目已有的 SetWindowSubclass / DefSubclassProc 模式，配合 WM_INITMENUPOPUP、WM_ENTERIDLE、WM_UNINITMENUPOPUP 获取当前原生弹出菜单，关闭时按窗口生命周期清理。

## 两层菜单排查

源码与真实窗口均未发现重复创建的菜单栏：“前端”“对齐”各只有一份。打开“前端”“对齐”“文件”时，均只存在一个属于验收进程的原生弹出菜单窗口。已移除引发布局差异和刷新叠影的整行自绘及类型切换。

## GitHub 检索与来源

实施前通过 GitHub 插件检索 Win32 ownerdraw menu、SetMenuItemInfo MIIM_FTYPE MIIM_STRING ownerdraw、WM_ENTERIDLE SetWindowSubclass，检查 [ReactOS 菜单实现](https://github.com/reactos/reactos/blob/master/win32ss/user/ntuser/menu.c)（GPL 系列许可证）和菜单测试，以及 [Microsoft Win32 菜单文档](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/menurc/using-menus.md)。未发现可直接复用、同时保留原生布局的圆点组件，未搬入这些仓库的实现代码；最小适配复用本项目原有 Windows 控件子类化和 GDI 绘制机制。

窗口取得与子类化遵循 [WM_ENTERIDLE](https://learn.microsoft.com/en-us/windows/win32/dlgbox/wm-enteridle)、[SetWindowSubclass](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-setwindowsubclass) 官方接口。先前 picojson、gpustat、pywebview 的实际复用内容与许可证继续见前一份验收文档。
